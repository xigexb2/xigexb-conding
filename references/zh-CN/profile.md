# 个人编码习惯与默认约定

[English](../profile.md) | **简体中文** | [规范索引](translations.md)

本文件记录 xigexb 已明确表达的习惯及既有规范。它们是作者的选择，不冒充语言标准或行业强制要求。具体仓库和当前任务可进一步收紧；调整时必须说明实际差异。

## P01 文本与格式

- 新增和修改的代码、脚本、配置与文档使用 UTF-8 无 BOM、LF
- 非空文本文件以一个 LF 结束，不保留额外尾部空白行；去掉行尾空白
- 手工代码默认空格缩进；Go 使用 `gofmt`，Makefile 的配方 Tab 等语法例外遵守官方工具
- Java 默认四空格；JSON、YAML 默认两空格；其他语言遵守既有格式工具
- Java 目标行宽 100 列，硬上限 120 列；不要为达标压缩多个语句、错误处理或注释
- 使用仓库实际存在的格式配置；不引用不存在的 IDEA 配置文件，不批量格式化无关文件

## P02 文件与包规模

| 文件类型 | 手工维护文件上限，含注释和空行 |
| --- | --- |
| `.java`、`.kt`、`.go`、`.rs`、`.c`、`.h`、`.cpp`、`.hpp`、`.js`、`.vue` | 360 行 |
| `.py`、`.ts`、`.tsx`、`.jsx`、`.swift`、脚本及其他主流语言源文件 | 380 行 |

- 所有手工维护源文件均不得突破 380 行；纯常量枚举也不得无限豁免
- **所有编程语言与实现技术强制执行：一个包或目录直接归属的同类源文件最多 20 个，生产、测试、声明、头文件和生成的第一方源码合并计数，子包与子目录独立计数**
- 设计阶段预估目录增长，接近上限前按领域、能力、协议或生命周期规划子包；禁止超限后随意搬文件或创建 `part1/part2` 空壳
- 语言支持命名包时同时维护包职责与依赖方向；无命名包的技术用职责目录和稳定导出边界表达
- JavaScript/TypeScript 各脚本后缀合并，C/C++ 源码及头文件合并，Python 源码与声明合并，样式后缀合并；不能通过换后缀、测试名或生成标记绕过
- 单类枚举、协议常量、平台变体与第一方生成代码均不豁免；生成器应按职责输出到适当子包
- 第三方依赖、构建产物和锁文件保留原始结构，范围单独标识；禁止把第一方源码挪入排除目录规避要求
- 所有语言的完整分组与设计拆分要求见 [目录规模规范](directory-structure.md)；未知语言仍受规则约束，检查器需补充识别后缀
- 按领域和稳定职责拆包，不为规模制造无意义的 Helper、接口、循环依赖或职责碎片

## P03 简体中文注释

- 手工新增的代码注释、文档注释与说明使用专业简体中文，API 标识符及 `SAFETY` 等工具标记可保留
- 注释覆盖职责、契约、单位、范围、可空性、所有权、并发边界、失败条件和不直观原因
- Java 的接口、类、Record、枚举、注解、构造器、方法及字段使用多行 Javadoc；局部变量按复杂度解释
- 接口定义行为契约，实现说明实现差异；使用 `{@inheritDoc}` 时仍补充本实现的线程和资源约束
- Go 导出注释保留以标识符开头的惯例，正文使用中文；Python、Rust 等采用各语言原生文档形式
- 注释段落和提交摘要末尾默认不加句号；协议引用、URL、代码片段和第三方许可证保留原文
- Java 类级默认记录 `@author xigexb`、真实版本和实际创建时间；不能把示例日期或 `1.0.0` 机械复制到所有类
- `@param` 名称必须匹配；构造器和 `void` 方法不写 `@return`；仅声明实际失败契约的 `@throws`

## P04 实现与设计偏好

- 单一职责、高内聚、低耦合，接口表达稳定契约，实现承担具体行为
- 在系统边界、可替换策略和测试隔离点使用抽象；避免给每个类机械配一个接口
- 采用与现实业务对象、状态、所有权和物理流程一致的模型
- 优先复用标准库、现有依赖和成熟框架；不自行重写已有可靠能力
- 高性能以有界资源、合理算法、批处理、减少往返和可测量结果为基础
- 对输入、错误、边界与异常回收完整处理；不以“绝对无 bug”作为未经证明的交付承诺

## P05 Java 与日志

- 新建 Java 项目默认评估 Java 25；已有项目以实际工具链为准，不自动升级
- 使用 SLF4J，字段名为 `logger`，采用 `private static final` 初始化
- 日志正文与业务动态键使用中文，参数格式统一为 `设备编号[{}],错误信息[{}]`
- 禁止日志字符串拼接；异常对象作为最后一个参数，避免同一失败逐层重复打印
- 结构化日志的机器字段、MDC 标识如 `traceId`、`deviceId` 使用团队稳定键名
- 业务时间点明确时区；耗时带单位，使用单调时钟测量
- Fory JSON 是部分既有 Java 项目的选择；仅在项目已采用时遵循，不扩展为所有项目的依赖

## P06 验证、SQL 与 Git

- Java 不新增仓库单元测试；编译、现有检查、临时运行验证和必要集成验证仍必须执行
- Go 行为或并发逻辑变更必须新增或更新对应单元测试；纯格式、注释修改运行已有检查
- Rust、C、C++、Python、前端按风险选择测试，不用只复述实现的断言充数量
- 不生成 SQL 留底文件；数据库验证优先只读，临时语句不落入源码仓库
- 正式迁移需要 SQL 文件时，先检查当前任务是否已明确授权这一例外；不得默认绕过约定
- 未获明确授权不执行 `git commit` 或 `git push`；只要求提交时仅本地提交
- 采用 `type(scope): 简体中文摘要`，英文小写类型，首行不超过 72 字符，不加末尾句号
- 合法类型：`feat`、`fix`、`refactor`、`perf`、`docs`、`style`、`test`、`build`、`ci`、`chore`、`revert`
- 显式路径暂存并审查暂存差异；保留用户和其他任务的修改，禁止破坏性覆盖

## P07 产品体验

- 页面应当好用：主任务明确、反馈及时、信息层级清楚、错误能够恢复
- 配色符合使用场景、品牌和平台习惯，以对比度和语义一致性验证，不宣称某种颜色普遍最好
- Web、iOS、Android、小程序遵循各自交互契约；不直接套用同一桌面页面

## 公开发布边界

仅发布通用规范和经筛选的工程经验。不要包含工作服务器、内网地址、账号、凭据、私有仓库标识、设备秘钥、客户数据或对话历史。
