# Rust

[English](../../languages/rust.md) | **简体中文** | [规范索引](../translations.md)

所有包/目录直接同类源码最多 20 个，测试、声明与第一方生成文件合并计数；设计时按职责划分子包，遵守 [统一目录规范](../directory-structure.md)

## R01 类型与所有权

- 读取 edition、MSRV、features、目标三元组和锁文件策略，单文件最多 360 行
- 公共类型与 trait 暴露最小稳定能力；状态优先用枚举与 newtype 表达，避免无效组合
- 优先借用、不可变值和明确移动；不能用到处 `clone()` 掩盖生命周期设计
- `Arc` 提供共享所有权，内部可变性仍需同步；不要把引用计数当作线程安全证明
- 公开集合与回调说明分配、顺序、所有权和 panic 契约
- 泛型与 trait object 按静态专门化、编译体积、动态扩展和热路径成本选择
- 不强制所有循环改成迭代链；选择更容易表达不变量且可优化的形式

## R02 错误与 panic

- 外部输入、网络、配置和持久化失败使用 `Result` / `Option` 与 `?` 传播
- 生产路径不以 `unwrap()` / `expect()` 掩盖可恢复失败；确证不变量要说明理由与影响
- 库提供可匹配的错误类型，应用边界补充上下文；不为了风格强制引入新错误库
- panic 策略核对 unwind/abort，析构和 FFI 边界不能依赖未知传播行为
- 序列化、反序列化和整数转换检查范围、长度、分配上限及不可信输入

## R03 unsafe 与 FFI

- `unsafe` 限定在最小模块，提供安全封装，解释调用前置条件与内部不变量
- 每个关键 unsafe 块用中文 `SAFETY` 说明指针对齐、初始化、有效范围、别名、生命周期及并发条件
- 不手工实现 `Send` / `Sync`，除非能证明跨线程与共享访问契约
- 外部布局使用适用的 `repr`；验证字段位宽、ABI、调用约定和链接目标
- C 字符串、回调、分配器和释放函数配对，明确由哪一侧释放以及是否可以跨线程
- 原始指针、`MaybeUninit`、`set_len`、Pin、自引用和原子操作需要专门审查
- 按实际 ABI 和配置处理 panic 边界，不允许未定义的跨语言展开

## R04 异步与并发

- 异步运行时沿用项目选择，不能把 Tokio 扩展成所有 Rust 工程的必需依赖
- 运行时工作线程中不做长时间阻塞；使用受控阻塞池，并说明已启动阻塞工作可能不能取消
- 跨 `.await` 持锁前核对锁类型和访问模式；避免持有不必要的共享状态保护
- 明确 future 被丢弃时的取消安全、半完成写入和资源回收
- 任务必须有所有者，保留 JoinHandle 或明确监督者；检查 panic、错误和关闭结果
- Channel 与队列有界，关闭时 drain、丢弃或持久化的策略明确
- `select!` 等组合检查分支取消、饥饿与重复执行，不能仅证明 happy path

## R05 验证

```text
cargo fmt --check
cargo check --locked
cargo clippy --all-targets -- -D warnings
cargo test --locked
```

- 命令依据项目实际警告策略调整，不自动给遗留项目引入全局 deny
- 特性互斥时建立特性矩阵，不盲目使用 `--all-features`
- unsafe、FFI 和解析器按风险使用 Miri、Sanitizer、fuzz 和属性验证，说明工具支持范围
- 嵌入式 `no_std` 区分主机测试、目标链接、仿真及板上验证
- 性能在 release 配置测量，记录目标 CPU、编译参数和分配行为

## R06 组织、导入与格式

- 遵循项目 Rust edition、工具链、rustfmt 配置和原生约定；继续执行单个源文件最多 360 行、每目录同类文件最多 20 个，测试与第一方生成源码合并计数
- 按实际能力保持 crate 与模块职责内聚；非叶模块以声明和重导出为主，必要时允许少量整合代码。叶模块可按主要类型或职责命名
- 优先显式导入；内联测试模块、局部枚举变体、刻意设计的非叶模块重导出、已批准 prelude 或互操作场景可按取舍使用通配导入
- 可行时每条 `use` 从同一模块导入；仅局部使用的 trait 在局部导入。外部自由函数优先带模块名，类型／trait 优先直接导入；名称冲突、生成代码、既有约定或可读性需要时调整
- 使用 rustfmt，并核对配置是否受项目稳定工具链／MSRV 支持；`#[rustfmt::skip]` 仅用于明确的可读性或生成代码需求，不作为个人格式偏好
- Chromium 专属的 crate 扁平目录和 `chromium::import!` 仅适用于实际 Chromium 构建环境，不覆盖本 Skill 强制的包／目录上限与 Cargo 目录结构

## R07 API、类型与 trait 设计

- 区分可复用库契约与应用代码：库关注适当的灵活性和稳定性，应用优先直接解决需求，避免提前泛化
- 只需借用数据时，优先接受 `&str`、`&[T]`、`&Path`、`&T`，避免无必要地要求 `&String`、`&Vec<T>`、`&PathBuf`、`&Box<T>`；确需具体类型语义时保留
- 可复用 API 只需遍历时可接受迭代器或 `IntoIterator`；适合惰性消费时可返回迭代器。需要索引、所有权、自然构造结果或更简单的应用代码时保留切片或拥有所有权的集合
- 仅在调用便利性对库 API 确有价值时考虑 `impl Into<T>`，同时评估泛型代码体积、类型推导和接口复杂度，不机械用于应用函数
- 布尔参数难以表达意图时使用有语义的枚举；多项领域数据优先具名字段，存在语义差异或不变量时使用 newtype；局部清晰的元组和单字段 newtype 仍适用
- 符合完整语义契约时实现标准 trait，等价时使用 derive；只有语义、成本、不变量和未来兼容性允许时才添加 `Copy`、`Clone`、`Default`、`Eq`、`Ord`、`Hash`
- 类型专属行为优先固有方法；存在真实多态、泛型 API 或合理扩展点时定义 trait。扩展 trait 使用 `Ext` 后缀，并考虑所属权和方法冲突
- 根据分派方式、对象兼容性、二进制大小、编译与扩展性选择泛型或 `dyn Trait`，不笼统宣称某一种始终更快
- 使用 `foo`、`foo_mut`、`set_foo`、`take_foo`、`replace_foo`、`with_foo` 等惯用访问器名称；适用时公开 `len` 同时提供 `is_empty`。闭包访问器应说明锁、重入及 panic 行为
- 不依赖外部 `#[doc(hidden)]` 实现细节；公开 `const fn` 应作为兼容性承诺审慎决定；运算符重载仅用于自然且有文档的语义
- 对可能演进的公开 enum／struct 评估 `#[non_exhaustive]` 以及对下游构造和匹配的影响；稳定的封闭模型可保持穷尽。忽略返回值可能造成错误时考虑 `#[must_use]`，避免重复标注已有属性的返回类型

## R08 诊断、安全与平台范围

- 对不需要额外原因的预期缺失使用 `Option`，可恢复且需要上下文的失败使用 `Result`；仅在目标允许时用 panic 表示真正违反的不变量
- 优先使用模式匹配或 `let-else`，避免先检查再 unwrap。确需因不变量而 panic 时优先使用有意义说明的 `expect`，不要把可恢复错误改为 panic
- 断言消息说明违反的不变量、调用误用和必要的安全上下文，不记录秘钥；长迭代器链难以理解时使用具名中间结果或循环
- Mutex 中毒提示不变量可能已损坏，不得盲目取出数据继续使用；如需恢复，必须定义并验证不变量修复策略，并遵循具体 mutex 实现语义
- 将 `unsafe` 限制在最小范围；每个 unsafe 块以简体中文说明安全依据，unsafe API 通过 Rust 的 `SAFETY`／`# Safety` 约定说明调用方义务。解释为何安全替代方案不足；性能理由需要测量证据
- 未经项目明确允许和实际工具链／目标论证，不引入不稳定特性。`catch_unwind` 仅对展开式 panic 有效，不能代替错误处理、资源不变量、abort 行为或 FFI 安全
- Chromium 对 async、标准线程、构建／导入和测试的专属限制，以及 Fuchsia 的同步／测试规则，仅在实际目标项目采用时适用。嵌入式 `no_std` 与硬件验证继续遵循目标平台要求
