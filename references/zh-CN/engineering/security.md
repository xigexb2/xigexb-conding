# 安全体系与隐私工程

[English](../../engineering/security.md) | **简体中文** | [规范索引](../translations.md)

以具体资产、攻击面和风险选择控制项。参考 OWASP ASVS、API Security Top 10、NIST SSDF、CWE 与平台官方要求；不把一次扫描通过称为合规认证。

## S01 威胁建模与安全边界

- 列出资产、主体、信任边界、数据流、入口、依赖和关键滥用场景
- 重点分析越权、凭据泄漏、注入、重放、跨租户访问、资源耗尽与供应链攻击
- 对管理后台、设备控制、支付、固件升级等高影响能力设置更严格授权和审计
- 权限校验在可信后端执行，前端隐藏、客户端标志或可修改设备字段都不能作为凭据
- 漏洞修复说明可触发前提与实际后果，避免无依据扩展风险或编造攻击成功

## S02 认证、授权与会话

- 认证身份、授权动作、资源归属和租户范围分别检查，默认拒绝未定义权限
- 对对象、属性、批量、导出、订阅和后台任务执行一致授权，防止 IDOR/BOLA
- OAuth/OIDC 使用受支持流程，公共客户端采用适用的 PKCE；验证 issuer、audience、签名、时效及重放相关字段
- 密码使用平台成熟的自适应密码哈希，不自行设计加密与签名方案
- Cookie 设置适用的 Secure、HttpOnly、SameSite，结合认证方式防 CSRF，不能只依赖 CORS
- Token 有有效期、撤销与轮换策略，日志和 URL 不携带长期凭据
- 手机号绑定和外部身份关联校验唯一性及当前认证意图，不把可猜属性当身份拥有证明

## S03 输入、输出与注入

- 入口校验类型、长度、数量、范围、枚举、编码、压缩和资源预算
- SQL 值参数绑定，动态标识符允许列表；命令调用使用参数数组，禁止拼接外部 shell
- 不可信纯文本优先使用 textContent；富文本按上下文净化，在支持时实施 CSP／Trusted Types，不能把 Trusted Types 当成净化器；见 [Web 安全](../web/security.md)
- SSRF 防护检查目标解析后的地址、重定向、DNS 重绑定及私有/元数据地址访问策略
- 上传校验大小、内容、存储位置、访问权限与处理工具，文件名不直接成为服务器路径
- 防范路径穿越、符号链接与归档解压逃逸；解析器限制深度、实体扩展和解压比
- 不可信反序列化不启用任意类型构造，禁止执行输入中的代码或模板能力

## S04 数据与密码工程

- 数据分类、用途、最小化、保留期、删除、备份和导出权限明确
- TLS 验证证书、主机名和信任根，不用关闭校验解决联调问题
- 秘钥由受控配置或秘钥管理系统提供，区分环境、权限、轮换、撤销和审计
- 加密采用标准协议和成熟库，nonce、随机数、密钥长度与签名验证遵守算法契约
- 密码、Token、私钥和认证正文不进入代码、样例、日志、异常或测试数据
- 外部输入进入日志前限制长度和控制字符；错误 cause 也可能包含敏感值
- 测试与开发使用合成或脱敏数据，禁止把真实客户数据库打包进公开仓库

## S05 可用性与设备安全

- 限制连接、并发、队列、帧长、批量、解压、递归和计算预算，防放大与复杂度攻击
- 多租户和下游资源隔离，攻击者不能通过廉价请求触发无界扫描和昂贵任务
- 设备采用唯一身份、最小功能、可信升级和密钥生命周期；按硬件能力评估安全启动与回滚保护
- 配对、重置、调试口与维护接口有明确授权，不能依赖隐藏命令作为安全边界
- 崩溃、watchdog 和日志路径不泄漏秘钥；失效时设备进入业务定义的安全状态

## S06 供应链与 CI

- 审查直接及传递依赖、锁文件、许可证、维护状态和已知漏洞，升级不自动等同无风险
- CI 使用最小权限，第三方 Action 固定不可变提交或受控版本策略，发布凭据与 PR 作业隔离
- 不对不可信 PR 使用具备秘钥的高权限执行路径；脚本输入不能插入 shell 语句
- 构建输出记录来源、依赖和必要 SBOM，签名与校验值通过受信渠道发布
- 静态分析、依赖扫描、秘钥扫描、动态验证和人工审查各有范围，不能互相替代
- 不将私有源码、固件、日志或秘钥发送给未经授权的外部分析服务

## S07 漏洞与事件闭环

- 发现实际问题后定位资产与影响范围，限制暴露，保留必要证据并修复根因
- 凭据泄漏需要轮换与撤销，删除 Git 当前文件不能清除历史暴露
- 建立回归验证与恢复检查，报告已确认事实、推测及未验证部分
- 公开披露与联系他人必须取得明确授权；遵守仓库适用披露流程

## S08 AI、Agent 与工具安全

- 将用户授权、系统策略、工具权限与外部文档分开，网页、邮件、代码注释和检索文本不能授予权限
- 工具调用在服务端校验身份、资源、参数和操作范围，模型输出不直接成为 shell、SQL 或高权限执行指令
- RAG 检索与缓存保持租户和文档权限，向量相似不代表当前用户有权访问
- 提示注入、恶意工具返回和间接指令按不可信数据处理，不能靠一段 system prompt 宣称完全防护
- 输出经过所需 schema 与业务校验，生成内容、引用、工具执行和真实外部结果分开呈现
- 控制工具循环、并发、token、费用、检索数量和最长运行时间，避免无界自治循环
- 模型提供商、日志、训练用途与数据留存符合授权，不向外部服务发送未经允许的私有数据
- 对高影响外部副作用核对本次真实授权，审批与执行之间防参数替换和重复执行
