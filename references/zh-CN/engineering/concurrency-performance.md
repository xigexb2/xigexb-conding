# 并发、资源生命周期与性能

[English](../../engineering/concurrency-performance.md) | **简体中文** | [规范索引](../translations.md)

## CP01 并发正确性

- 说明共享数据的所有者、读写路径和同步机制；不可变数据、消息传递、局部分片优先
- 不把“使用并发容器”当作复合业务操作原子的证明；检查检查后执行、读改写和跨键不变量
- 使用原子操作前说明状态机、内存可见性和 ABA 风险；无锁实现需要进展性及回收依据
- 锁顺序一致，临界区短；共享状态锁内不调用外部回调、等待 Future 或执行网络及磁盘 I/O
- 若必须序列化某项 I/O，明确专用串行通道与所有权，不能用全局状态锁偶然实现
- 线程、协程和任务切换不自动传递 MDC、事务、授权上下文或线程局部资源
- 数据竞争检测通过不等于没有死锁、逻辑竞争、饥饿或线性化错误

## CP02 有界资源

| 资源 | 必须明确的边界 |
| --- | --- |
| 队列 | 最大长度、满载行为、等待期限、关闭与积压处理 |
| 缓存 | 项数或权重、失效、淘汰、击穿控制、回源并发 |
| 在途请求 | 总量、单租户配额、截止时间、取消与回收 |
| 连接与线程 | 上限、等待、隔离、闲置回收和退出行为 |
| 批处理 | 条数、字节数、等待时间、部分失败与拆包 |
| 重试 | 条件、次数或总时限、退避、抖动及幂等性 |
| 静态只读表 | 最大预期规模、发布时校验与不可变性 |

虚线程和 Goroutine 都不是无限资源。不要用廉价任务掩盖数据库连接耗尽、下游限流或堆内存增长。

## CP03 截止时间与取消

- 入站请求建立总截止时间；下游预算受剩余总时间约束，不能每一层重新获得完整超时
- 取消必须传播到实际 I/O 或任务；无法取消时记录工作仍在进行并回收观察端资源
- 超时、正常完成和取消竞争时，只允许一个确定的完成结果，重复完成无副作用
- 订阅、定时器、请求表和缓冲区必须在所有终结路径清理
- 重试避免多层叠加；拒绝和超载优先快速反馈，不在过载时放大请求
- 关闭顺序明确：停止接收、停止派发、有限等待、取消剩余任务、释放资源

## CP04 性能设计

- 先确定瓶颈属于 CPU、I/O、锁竞争、内存、GC、序列化、网络往返还是下游容量
- 优先改进算法与访问模式：批量读取、减少 N+1、请求合并、数据局部性、避免重复解析
- 用不可变数据或独占所有权减少复制；异步边界的引用安全优先于零拷贝口号
- 对象池只用于分配或外部资源成本已证实高且生命周期明确的场景；评估竞争、清理和保留内存
- 避免热路径反射扫描、无界集合构造、重复序列化和无目的全量排序
- 缓存是派生数据，明确源数据、失效及一致性窗口；缓存失败不得绕过授权
- 分片键考虑热点、租户公平和顺序要求；并发度不能超过最薄弱的下游资源预算

## CP05 测量方法

- 给出基线、硬件、系统、运行时、编译参数、数据规模、请求分布和依赖状态
- 区分微基准和端到端负载；预热、重复采样、隔离死代码消除和常量折叠
- 报告吞吐、p50/p95/p99、错误率、排队、CPU、内存峰值及分配速率
- 检查协调遗漏、客户端自身饱和和不真实的命中率；开环与闭环压测说明选择
- 评估稳定负载、突发、冷启动、长时间运行和降级恢复
- 容量估算可以用 Little 定律指导预算，但平均值不能代替尾延迟和突发验证
- 性能变化同时检查正确性、资源泄漏和公平性，不能只比较单次耗时

## CP06 观测

- 日志、指标和追踪分工明确：日志解释事件，指标描述趋势，追踪定位跨服务路径
- 指标标签禁止无限设备编号、用户编号、完整 URL 等高基数维度
- 捕获并恢复上下文，避免线程复用污染；采样不能隐去关键安全与资金审计
- 重复失败限速或聚合；不要在每条设备消息上打印完整 INFO 报文
- 告警围绕用户影响和资源饱和，能够对应处理动作
