# 验证、调试与交付证据

[English](../verification.md) | **简体中文** | [规范索引](translations.md)

## Q01 按风险选择证据

| 修改 | 最少评估的验证 |
| --- | --- |
| 文档与格式 | 文本编码、链接、示例和限定范围差异 |
| 业务行为 | 输入边界、错误、授权、不变量和回归场景 |
| 并发 | 取消、超时、竞态、关闭、重复完成与泄漏 |
| 协议 | 已知线向量、畸形长度、方向、独立实现互操作 |
| 数据库 | 约束、事务、冲突、执行计划和迁移影响 |
| UI | 主任务、状态、响应式、键盘、读屏与真实数据 |
| 系统与硬件 | 目标构建、仿真、时序或板测及明确缺口 |
| 性能 | 基线、代表性负载、资源与尾延迟 |

遵守个人习惯：Java 不新增仓库单测；Go 行为变更需要对应单测。不能用这一区别省略必要的运行验证。

## Q02 有意义的测试

- 测试外部可观察结果与业务不变量，不镜像私有实现或只匹配文字
- 使用代表性边界、失败注入、取消、重复、乱序和资源回收案例
- 属性与差分验证采用独立性质或参考实现，避免两边共享同一错误
- 控制时钟、随机种子和外部依赖，隔离临时目录与端口；不要用长 sleep 掩盖同步缺陷
- Mock 只证明契约假设下的逻辑，不代表真实数据库、网络和设备已经集成
- 测试数据不含真实凭据或客户信息，临时验证产物放任务隔离目录

## Q03 系统化调试

1. 记录实际症状、预期行为、版本和可复现步骤，保留必要日志与抓包
2. 沿输入、转换、状态、外部调用和响应定位首次偏离点
3. 提出可证伪假设，设计最小实验，一次改变一个关键因素
4. 修复根因及必要边界，不用吞异常、延长超时或盲目重试掩盖问题
5. 复验触发场景和邻近风险，给出证据与仍未知的条件

日志中的超时、扫描和异常不自动证明设备离线、攻击成功或数据库丢失。证据不足时保留多个候选原因。

## Q04 终检

- 最终限定范围 diff 与需求一致，已有用户修改保持完整
- UTF-8 无 BOM、LF、末尾换行、行数、Java 行宽及所有语言的目录同类文件数符合约定
- 检查新增依赖、版本变化、锁文件、配置默认值、许可与秘密信息
- 命令、退出码和关键结果可复现；环境失败与实现失败分别报告
- 成功标准以最终代码和实际运行结果为准，不能只引用早先版本的通过记录
- 对通过后的同一范围不无理由重复扩大验证；存在新修改或未解决风险时补充对应检查

## Q05 证据等级

按实际情况表达：静态检查通过、编译通过、单元/临时验证通过、真实组件集成通过、仿真通过、真机/板测通过、代表性负载通过。任何一级都不自动包含下一级，不能笼统宣称“生产就绪”或“无漏洞”。

## Q06 Skill 行为验收场景

维护本 Skill 时至少人工走查以下决策，并记录是否出现相反规则：

- Go 格式化保留 gofmt 的 Tab，Java 使用空格，不能被通用规则覆盖
- 所有语言超过每目录 20 个同类源码时必须按职责拆包，混合后缀、测试与第一方生成文件不能绕过
- 未知语言通过显式分组进入发现与规模校验，不能因未内置后缀而默认通过；完整 YAML 校验应拒绝语法错误、重复键和不符合约定的类型
- Java 25 不因过时钉住说明机械替换 synchronized，不默认启用预览 API
- Netty 消息转发、自动释放和异步保留区分所有权，不重复释放
- 用户只要求提交时不推送；制作公开发布材料时不擅自上传私有仓库
- Vue 局部修复不强制迁移框架或 API 风格，旧请求不能覆盖新状态
- 设备下发成功不伪造成设备执行成功，超时结果保留未知语义
- iOS 的 pt、Android 的 dp 和 Web 的 CSS px 不混用
- 电路 ERC/DRC、RTL 仿真及固件编译不被描述为硬件签核或板级验收
- SQL 参数化、租户隔离及数据库唯一约束不被缓存锁替代

这些是维护用的行为预期，不代表已经开展独立模型评测或完成行业认证。
