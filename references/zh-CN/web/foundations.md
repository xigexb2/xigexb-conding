# 现代 Web 平台基础规范

[English](../../web/foundations.md) | **简体中文** | [规范索引](../translations.md)

## WB01 兼容策略

- 选择 API 前明确支持的浏览器版本、嵌入式 WebView、辅助技术以及既有框架和构建约束
- 将 Baseline 与浏览器兼容数据作为证据，仍以项目实际目标矩阵为准；同一功能的子特性、已知缺陷和 polyfill 限制可能不同
- 当原生 HTML/CSS/DOM 能满足任务、无障碍和目标浏览器时优先采用；不满足时验证真实降级或有针对性的回退
- Origin Trial、浏览器标志、单浏览器、实验性和快速变化的能力应先获得项目明确授权，并核验特性与版本，不能静默启用
- 不为使用本规范自动安装或运行未固定版本的网络 CLI、强制遥测或替换现有成熟框架与组件

## WB02 语义、布局与 CSS

- 优先使用语义元素、原生按钮、链接、标签、标题、列表、表格和地标；保持文档顺序与键盘阅读顺序
- 根据内容约束选择 Grid/Flex、内在尺寸、换行、容器查询或媒体查询，避免只针对固定视口缩放
- 语义应随书写方向变化时使用逻辑属性；镜像会改变原有意图时保留物理方向
- 沿用仓库级联约定；在支持且有收益时采用级联层、作用域选择器、`:where()`、`:is()` 和自定义属性，不为此全量重写样式
- 浏览器支持时可用 `:has()` 等选择器表达状态样式并验证回退；不能假设全部选择器子特性表现一致
- 统一语义设计令牌、系统主题、`color-scheme`、`prefers-color-scheme`、对比度、强制颜色、文字缩放和减少动效
- 较新的色彩空间、CSS 函数、字体、嵌套、滚动和锚点定位须针对目标浏览器核验，适用时用 `@supports` 隔离增强
- 自定义元素与 Shadow DOM 需要可访问名称、键盘行为、生命周期清理、样式边界和表单集成；采用前评估 SSR 与升级时序

## WB03 国际化文字与布局

- 翻译、长文本、缩放、RTL 和不同书写方向下保持源内容可读，避免意外溢出或裁剪
- 日期、时间、数字、货币和日历按语言地区格式化；绝对时刻、当地日期和时区分别建模
- 按实际目标核对 `Intl`、`Temporal` 与时区数据；不能假设 `Temporal` 已普遍可用
- 字体与回退度量应减少布局偏移，同时保证中英文覆盖和真实授权

## WB04 验证证据

在目标浏览器与框架中检查实际断点、键盘顺序、可见焦点、读屏语义、缩放、减少动效、强制颜色和 hydration。完整固定版本专题见[上游索引](catalog.md)。
