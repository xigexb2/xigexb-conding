# 现代 Web 性能与测量

[English](../../web/performance.md) | **简体中文** | [规范索引](../translations.md)

## WP01 测量真实用户体验

- 按页面、设备、网络和版本建立有代表性的 LCP、INP、CLS 现场与实验室基线；使用当前指标定义并说明样本局限
- 分解 LCP 的服务端响应、资源发现、加载等待、传输和渲染等待；修改优先级前先确定真实 LCP 元素
- 排查 INP 时定位慢交互、输入等待、处理器耗时、呈现等待、长任务及布局／渲染工作；在代表性设备验证优化
- 使用布局偏移归因诊断 CLS；为媒体和嵌入内容预留空间，处理动态插入与字体回退度量，并考虑合规的用户交互排除条件

## WP02 加载与渲染

- 让首屏关键内容和 LCP 资源尽早被发现；不要对实际 LCP 图片使用懒加载，并为图片／视频预留尺寸
- 按内容和设备选择响应式图片、现代格式、压缩与缓存；同时验证视觉质量、CPU、流量和无障碍
- 将 `fetchpriority="high"`、preload、preconnect、prefetch 限定于确有证据的重要资源；过度提高优先级与推测请求可能造成竞争或隐私成本
- 根据顺序要求选择 `defer`、模块脚本或 `async`；减少阻塞解析和无必要的第三方工作。内联关键 CSS 前评估实际收益及缓存、CSP、维护代价
- 推迟确实处于屏幕外的工作；支持时使用适当内在尺寸的 `content-visibility`，同时验证页内搜索、无障碍和布局稳定性
- 设置合适的缓存策略和资源版本；检查过期内容、回滚及 CDN 行为，不能盲目缓存个性化响应

## WP03 调度与可观测性

- 在安全边界拆分主线程长任务；评估 `scheduler.yield()`、优先级 API、Worker 或兼容回退，不假设取消和执行顺序语义
- 合并 DOM 读取与写入；在引入复杂缓存或动画机制前先减少多余 JavaScript 与重复渲染
- 降低非关键网络与后台工作的优先级、限制并发，不为未请求的功能下载数据
- 性能遥测须符合授权、隐私、采样和数据最小化要求，避免不必要地发送 URL、标识符或用户输入
- 以测量结果选择方案，不无条件禁止依赖或自动引入 polyfill；复验加载、交互、错误和无障碍

## WP04 验证

在获得授权时使用浏览器性能工具和真实用户测量，在代表性设备、网络及任务流程下比较基线与修改结果。[上游索引](catalog.md)提供 LCP、INP、CLS、调度、图片和导航专题。
